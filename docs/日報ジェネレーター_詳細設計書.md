### 必須ルール

- `taikinGroups` / `morningGroups` は「案件カテゴリ → タスク配列」のネストを維持する。

- 案件カテゴリは画面上ではそのまま表示し、出力時だけ `＜案件名＞` に変換する。
- `tacoContacts.name` は素の名前で保存する。＠は保存せず、出力時だけ付与する。
- 同僚の実名・Slack IDはコードに直接書かず、本人のFirestore領域にのみ保存する。

## 2. 処理ロジック

### 3まとまり出力

- **入力**: `reportWork.greeting` / `reportWork.taikinGroups` / `reportWork.morningGroups`
- **処理**:
  - 退勤報告タブ＝本日分、朝会報告タブ＝明日分として扱う。
  - 案件カテゴリは画面ではそのまま、出力時だけ `＜案件名＞` で囲む。
  - タスクは `作業時間h｜タスク名` で出力する。
  - 出力は必ず3まとまり生成する（空でも枠は出す）。
- **出力**:
  - まとまり1: 退勤報告 ＝ 挨拶文 ＋ 本日分
  - まとまり2: 今日やったこと ＝ 本日分のみ
  - まとまり3: 明日やること ＝ 明日分のみ
- 実出力に `── まとまり名 ──` の区切り線を含めない（区切り・見出しは画面プレビュー専用）。

### タコス投稿生成

- **入力**: タコスブロック配列（宛先配列 / 個数 / 文面）、モード（merge / split）
- **共通処理**:
  - 宛先なし・文面なし・個数なしのブロックは投稿対象外。
  - 登録名に＠は保存しない。出力時に各宛先の先頭へ＠を付ける。
  - 投稿末尾に🌮を個数分付ける。
  - 1投稿内の複数ブロックは空行で区切る。
- **文面フォーマット**:
  ```
  ＠宛先A
  文面A

  ＠宛先B ＠宛先C
  文面B
  🌮
  ```
- **モード1: 投稿をまとめる（既定）**: 同じ個数のブロックを1投稿にまとめ、違う個数だけ別投稿。1投稿の宛先全員に同じ個数が付く。
- **モード2: 個別で送る**: 宛先1人ずつ別投稿。連名ブロックも宛先ごとに分割。同じ文面でも宛先が複数なら投稿を分ける。各投稿の消費数は 1人 × 個数。
- **出力**: ライブプレビュー用の投稿配列／各投稿の個別コピー対象／全投稿の一括コピー対象。

### 一括インポート

- **入力**: 設定タブのテキストエリア
- **処理**: 改行で分割 → 各行 trim → 空行除外 → 先頭の `@` / `＠` を除去 → 既存登録名と重複除外 → 貼り付け内の重複も除外。
- **出力**: `tacoContacts` に追加。追加件数を顧客目線で表示（例「N人を登録しました」／「新しい相手はありませんでした」）。

### タコス消費累計

- **入力**: コピー対象投稿、`tacoUsage`
- **処理**:
  - 現在日付が `tacoUsage.date` と違う場合、`consumed` を0に戻す。
  - 個別コピー時はその投稿の 人数 × 個数 を加算。
  - 一括コピー時は全投稿の消費数合計を加算。
  - コピーした時点で送信相当とみなす。
  - **個別コピー後に一括コピーした場合の二重加算は許容する**（コピー＝送信とみなす仕様）。
  - **本日の消費メーターは手動で調整できる**（実態と合わないときユーザーが直せる）。
  - 上限に近い／到達／超過の表示を顧客目線で行う。
- **出力**: 更新後 `tacoUsage`、タコスタブ固定ヘッダーの消費メーター。

## 4. 移植マッピング（現行 index.html の実物に基づく確定版）

### Firebase初期化（そのまま移植）

```js
// compat版 CDN
firebase.initializeApp(firebaseConfig);
const auth = firebase.auth();
const db = firebase.firestore();
let currentUser = null;
```

### `googleLogin()`
- 現行処理: `new firebase.auth.GoogleAuthProvider()` → `auth.signInWithPopup(provider)`、失敗時 `showToast(...)`。
- 接続先: 設定タブのGoogleログインボタン。
- 設計: シグネチャ変更なし。ログイン成功後のデータ読込は `auth.onAuthStateChanged` で受ける。エラー文言は現行の文字化け文言ではなく顧客目線の日本語に置換。

### `googleLogout()`
- 現行処理: `auth.signOut()`。
- 接続先: 設定タブのログアウトボタン。
- 設計: シグネチャ変更なし。ログアウト後は未ログイン表示、localStorageバックアップを継続利用。

### `userDocRef()`
- 現行処理: 未ログインなら null、ログイン済みなら `db.collection('users').doc(currentUser.uid)`。
- 設計: 保存先は `users/{uid}` に固定。**ループ内でFirestore取得しない。ユーザー文書を一括取得する。**

### `loadFromFirestore()`
- 現行読込キー: `tCats` / `tMemo` / `aCats` / `aMemo` / `greeting` / `presets` / `webhook`。
- 設計: シグネチャ変更なし。既存データは引き継がないため旧→新キーの移行分岐は作らない。新キーを一括読込。データがなければ初期状態を `saveToFirestore()` で作成。読込後 localStorage にもキャッシュ。
- 新読込キー: `reportWork` / `reportPresets` / `tacoContacts` / `tacoTemplates` / `tacoUsage` / `webhookUrl` / `theme` / `accentColor`。

### `saveToFirestore()`
- 現行制御: `userDocRef()` がなければ何もしない。`_saving` 中なら `_saveQueued = true` で戻る。`ref.set(..., { merge: true })`。保存後キューがあれば再実行。
- 設計: シグネチャ変更なし。**`_saving` / `_saveQueued` の多重保存防止を維持。`merge: true` を維持。** 保存中身は新データ構造へ置換。旧キーとの互換保存はしない。
- 新保存キー: 上記 + `updatedAt`。

### `debouncedFirestoreSave()`
- 現行処理: 未ログインなら何もしない。既存タイマークリア → 1500ms後に `saveToFirestore()`。
- 設計: シグネチャ変更なし。入力中の保存頻度抑制のため維持。日報入力・設定変更・タコス登録・テンプレ更新で呼ぶ。**コピー時のタコス消費加算は即時保存を優先。**

### localStorage
- 現行キー: `state`（tCats等）/ `presets` / `webhook_url` / `theme`。
- 設計: 未ログイン・オフライン用バックアップとして維持。旧キーからの移行は不要。
- 新キー: `daily_report_state_v5`（日報・タコス・設定の新状態）/ `webhook_url`（現行キー維持）/ `theme`（現行キー維持）。

### `postToSlack(text)`
- 現行処理: `fetch(WEBHOOK, { method: POST, mode: no-cors, header: Content-Type: application/x-www-form-urlencoded, body: payload= + JSON{text} })`。
- 設計: シグネチャ変更なし。日報タブのSlack送信だけに使う。**タコスは実送信せずコピーのみ。** 3まとまりを送る（実出力に区切り線は含めない）。Webhook未設定時は「Slack送信先を設定してください」のような顧客目線文言。

## 7. push前の修正項目（1回目の実装をスマホ実機で確認して発見）

1回目の実装をスマホで確認したところ、以下4点の不具合・要件漏れが見つかった。push の前にこれらを修正する。

### 7-1. 下部ナビがスマホで固定されていない
- **症状**: スマホで開くと下部ナビ（日報／タコス／設定）が画面下に固定されず、コンテンツを最後までスクロールしないと出てこない。
- **原因**: 下部ナビが position 固定になっておらず、コンテンツ末尾に配置されている。
- **修正**: 下部ナビを position 固定で画面下に常時表示する。モバイルブラウザのアドレスバー伸縮で `100vh` がずれる対策を入れる（`100dvh` の使用、またはJSでの高さ補正）。コンテンツ側に下部ナビの高さ分の `padding-bottom` を確保し、最下部の項目が隠れないようにする。ヘッダーも同様に固定。

### 7-2. セグメント直下のワンタッチコピーボタンが無い（旧機能の復活）
- **症状**: 旧版にあった、セグメントバー直下のコピーボタンが新版に無い。
- **修正**: 日報タブの「退勤報告／朝会報告」セグメントバーのすぐ下にコピーボタンを置く。動作は「今表示しているタブの内容を丸ごとコピー」。退勤報告タブ表示中に押す → 退勤報告（挨拶＋本日分）をコピー。朝会報告タブ表示中に押す → 朝会報告（明日やること＝明日分）をコピー。出力プレビューまでスクロールせず、その場でコピーできるようにする。コピーする中身は出力プレビューの該当まとまりと同じ。

### 7-3. コピー内容がタブと逆（データ紐付けの入れ違い）
- **症状**: 退勤報告タブでコピーすると朝会報告の内容がコピーされる（逆も同様）。
- **原因**: コピー処理が参照するデータがタブと入れ違っている（退勤報告タブが `morningGroups` を、朝会報告タブが `taikinGroups` を参照している）。
- **修正**: タブとデータの紐付けを正す。**退勤報告タブ ＝ `taikinGroups`（本日分）、朝会報告タブ ＝ `morningGroups`（明日分）**。7-2 のワンタッチコピーも、この正しい紐付けに従う。

### 7-4. 更新するとログアウトする（ログイン保持の欠落）
- **症状**: Googleでログイン済みでも、ページを更新すると未ログインに戻る。旧版では保持されていた。
- **原因**: ページ読み込み時にログイン状態を復元する処理が欠けている（または persistence を SESSION/NONE にしてしまっている）。
- **旧版の実装（これに合わせる）**:
  - 旧版は `setPersistence` を明示的に呼んでいない。**Firebase Auth のデフォルト（`browserLocalPersistence` ＝ ブラウザに保持）に任せている。**
  - `initFirebase()` の中で `auth.onAuthStateChanged(user => { currentUser = user; ... })` を登録している。これがページ読み込み時に発火し、保存済みのログイン情報から `currentUser` を復元し、UI（ログイン状態表示・Firestore読込）に反映する。
- **修正**: 旧版と同じく、(1) persistence はデフォルト（`browserLocalPersistence`）のまま、明示的に SESSION/NONE にしない。(2) Firebase初期化時に `auth.onAuthStateChanged` を登録し、その中で `currentUser` を復元してUIに反映する。これでリロードしてもログインが保持される。

### 7-5. 修正後の確認（スマホ実機）
- 上記4点はいずれも、コードの存在チェックだけでは判定できない。修正後、必ずスマホ実機で次を確認してから push する。
  - 下部ナビが最初から画面下に固定で出ているか（スクロールしても消えないか）。
  - セグメント直下のコピーボタンが、今開いているタブの内容を正しくコピーするか（退勤報告タブ→退勤報告、朝会報告タブ→明日やること）。
  - ログイン後にページを更新してもログインが保持されるか。
