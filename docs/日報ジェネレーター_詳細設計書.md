## 0. 実装概要

- 実装版HTMLのUI構造、CSS、画面関数を土台にする。
- Firebase Auth、Firestore、Slack送信は旧 `index.html` の関数名を維持して移植する。
- すべてを1つの `index.html` に統合する。
- 外部ビルドや生成バンドルに依存しない。

## 1. データ設計

### 1-1. state

```js
state = {
  tab: 'report' | 'tacos' | 'settings',
  day: 'today' | 'tomorrow',
  today: Category[],
  tomorrow: Category[],
  greeting: string,
  presets: string[],
  contacts: TacoContact[],
  templates: TacoTemplate[],
  blocks: TacoBlock[],
  tacoMode: 'merge' | 'split',
  accumulated: number,
  usageDate: string,
  webhook: string,
  theme: 'light' | 'dark',
  tone: string,
  editingContactId: number | null,
  editContactName: string,
  editContactMemberId: string,
  editingContactBackup: { name: string, memberId: string } | null
}
```

### 1-2. 日報

```js
Category = {
  id: number,
  category: string,
  tasks: Task[]
}

Task = {
  id: number,
  hours: number,
  name: string
}
```

- `today` は退勤報告として出力する本日分。
- `tomorrow` は朝会報告として出力する明日分。
- `groupsOf()` は現在選択中のタブのデータを返す。
- `state.day === 'today'` では `today`。
- `state.day === 'tomorrow'` では `tomorrow`。
- 出力では案件名に `＜＞` を付ける。

### 1-3. タコス

```js
TacoContact = {
  id: number,
  name: string,
  memberId: string,
  freq: number
}

TacoBlock = {
  id: number,
  recipients: Recipient[],
  count: number,
  body: string
}

Recipient = {
  name: string,
  memberId: string
}

TacoTemplate = {
  id: string,
  label: string,
  body: string
}
```

- `TacoContact.memberId` は Slack のメンバーID。空文字は「未登録」を意味する。
- `TacoContact.freq` は宛先に選ばれた回数。宛先候補の並び順にのみ使う。
- `TacoBlock.recipients` は名前の配列ではなくオブジェクトの配列。宛先に選んだ時点の名前とメンバーIDを控えるため。連絡先マスターを後から編集しても、作成済みブロックの宛先は変わらない。
- `TacoBlock.id` はブロック一覧の中で一意でなければならない。重複するとブロックの検索・削除が別のブロックに当たる（5-3 参照）。
- 同名の `TacoContact` を許容する。したがって名前は連絡先を一意に特定するキーにならない。宛先選択・更新は `TacoContact.id` またはメンバーIDで行う。
- 宛先初期値は空。
- 実名やSlackメンバーIDはコードに書かない。ユーザーが登録したデータとして扱う。

## 2. レイアウト設計

### 2-1. 固定シェル

- `.app` は `height: 100vh; height: 100dvh;`。
- `.header` は `position: fixed` で上部固定。
- `.subheader` は日報/タコス用の固定補助ヘッダー。
- `.nav` は `position: fixed` で下部固定。
- `.scroll` は絶対配置のスクロール領域。
- `.scroll` は下部ナビ分の `padding-bottom` を持つ。
- タブごとに `.app[data-tab="..."] .scroll` の `top` を切り替える。
- `.tab` には再描画時の `animation` を付けない。
- 入力、タスク追加、タコス変更などの通常操作で画面全体をフェードさせない。
- タスク名、案件名、挨拶文、タコス本文の `oninput` では `render()` を呼ばない。
- 日本語IMEの変換候補を維持するため、入力中のDOM差し替えを避ける。

### 2-1-1. スクロール位置の記録と復元

- `render()` は `render({ scrollToTop })` の形で呼び出しオプションを受け取る。既定は現在位置の維持。
- 先頭表示は `renderFromTop()` に分離し、`App.go()`（タブ切り替え）だけがこれを呼ぶ。グローバルなフラグ変数で先頭表示を制御しない。どこで立てたフラグがいつ効くのかを追えなくなるため。
- `render()` の先頭で、外側スクロール `.scroll` と、設定タブの連絡先一覧 `.contact-scroll` の `scrollTop` をそれぞれ記録する。
- `innerHTML` 差し替えの後、同じ `render()` 内で同期的に復元する。`setTimeout` / `requestAnimationFrame` 等で遅延させない。遅延させると先頭が一瞬描画されるチラつきが出る。
- 復元の順序は「フォーカス復元 → スクロール復元」とする。フォーカス移動がスクロール位置を動かすため、スクロールを最後に確定させる。
- フォーカス復元は `el.focus({ preventScroll: true })` を使う。未対応環境では例外を捕捉して通常の `focus()` にフォールバックし、その場合も直後のスクロール復元で位置が戻る。
- 連絡先一覧の内側スクロール要素には `.contact-scroll` クラスを付け、記録・復元の対象として特定できるようにする。
- タブごとに直前のスクロール位置を覚える機能は付けない。

### 2-2. 日報タブ

- `viewSubheader()` で退勤報告/朝会報告セグメントとワンタッチ流用ボタンを表示する。
- `viewReport()` は `groupsOf()` の結果を編集対象として表示する。
- 退勤報告タブでは `today` を表示・編集する。
- 朝会報告タブでは `tomorrow` を表示・編集する。
- 挨拶文カードは `state.day === 'today'` のときだけ表示する。
- 朝会報告タブでは挨拶文カードを出さない。

### 2-2-1. 並び替え（ドラッグ）

- HTML5 Drag and Drop API（`draggable` / `ondragstart` / `ondragenter`）は使わない。マウス専用でタッチに反応しないため。
- Pointer Events（`pointerdown` / `pointermove` / `pointerup` / `pointercancel`）で実装し、マウスとタッチの両方に対応する。
- ハンドル要素（⠿）に CSS `touch-action: none` を指定し、掴んだハンドルに `setPointerCapture` する。
- 並び替え対象は、案件カテゴリ（カテゴリ一覧内）と、同一カテゴリ内のタスク。タスクはカテゴリをまたがない。
- `pointerdown` 時に、リスト内の各要素の位置・高さ・要素間の間隔を取得して保持する。
- ドラッグ中、掴んだ要素は `transform: translateY()` でポインタに追従させ、浮き上がりの影と軽い拡大（scale 1.03 程度）を付ける。
- ドラッグ中、他の要素は「新しい並び順から積み上げ計算した位置」へ `transform` で移動し、CSS transition でリアルタイムに避ける。
- ドラッグ中は `render()` を呼ばない。DOMの再生成を行わない（掴んだ要素が消えて中断する既知の不具合の原因）。
- タスクをドラッグ中は、親カードの `overflow` を一時的に `visible` にし、カード外への描画見切れを防ぐ。
- `pointerup` で並びを確定する。確定時は transition を一時的に無効化してから `transform` を解除し、DOM順序と `state` 配列の順序を更新する。着地のジャンプを出さない。
- 確定後は保存対象にする（`persist()`）。

### 2-2-2. 稼働時間の合計表示と色分け

- 合計時間表示（計 X.Xh）はviewSubheader()が描画する。viewReport()は合計時間を出力しない。
- 合計計算は共通関数に切り出し、viewSubheader()から呼ぶ。
- 日報タブの .app[data-tab="report"] .scroll のtopは、固定サブヘッダーの高さぶん下げる。
- 判定は0.5刻みの丸め後の合計で行う: Math.round(sum * 2) が 16 超なら赤、16 未満なら黄、16 ちょうどなら緑。
- 赤・黄のときは文字サイズを通常より大きくする。緑のときは通常サイズのまま。
- 赤は var(--danger)、緑は var(--ok)、黄はテーマ変数の警告色（ライト/ダーク両テーマ定義）。
- 合計計算は既存仕様どおり、タスク名が空のタスクを除外した合計とする。

### 2-3. ワンタッチ流用ボタン

- `App.quickCopy()` が担当する。
- Clipboard API は使わない。
- 退勤報告タブでは `朝会報告の内容をコピー` と表示する。
- 退勤報告タブで押すと `state.today = cloneGroups(state.tomorrow)` を実行する。
- 朝会報告タブでは `退勤報告の内容をコピー` と表示する。
- 朝会報告タブで押すと `state.tomorrow = cloneGroups(state.today)` を実行する。
- `cloneGroups()` は案件カテゴリとタスクを新しい `id` で複製する。
- 挨拶文はコピーしない。
- 実行後は `render()` し、保存対象にする。

### 2-4. タコスタブ

- `viewSubheader()` でタコス固定サブヘッダーを返す。
- タコス固定サブヘッダーは `class="subheader meter"` にする。
- 固定サブヘッダー内に `タコスを贈る` タイトルを表示する。
- 固定サブヘッダー内に `本日のタコス消費` と `入力中の消費見込み / 5` のゲージを表示する。
- ゲージ値は `tacoDraftConsumption()` で計算する。
- `.app[data-tab="tacos"] .scroll` は固定サブヘッダーの高さぶん下げる。
- `viewTacos()` の本文先頭には別の「タコスを贈る」見出しブロックを置かない。
- 本文はすぐ宛先+文面ブロックから始める。
- 出力プレビュー内で `merge` / `split` を切り替える。
- コピーまたはSlack送信時に `accumulated` を加算する。
- 設定画面には `accumulated` の手動調整欄を置かない。

### 2-4-1. 宛先候補の生成

- 候補は `state.contacts` を `freq` の降順で並べる。安定ソートを用いるため、同じ `freq` では `state.contacts` の並び（登録順）が保たれる。
- `memberId` が空の連絡先は候補から除外する。メンションが成立しない投稿文を生成させないため。
- 既にそのブロックの宛先になっている相手は候補から除外する。判定は名前とメンバーIDの両方の一致で行う（同名の別人を誤って除外しないため）。
- `<option>` の `value` は連絡先の `id` とする。名前を値にすると同名の相手を区別できないため。

### 2-4-2. 宛先の選択と解除

- `App.pickRecipient(blockId, contactId)` は、渡された連絡先IDから対象の連絡先を引き、`{ name, memberId }` をブロックの `recipients` に追加する。
- 追加時に対象連絡先の `freq` を1増やす。既に同じ宛先が入っている場合は追加も加算もしない。
- `App.removeRecipient(blockId, recipientIndex)` は配列の添字で削除する。名前一致で削除すると、同名の宛先が2件ある場合に両方消えるため。
- 宛先から外したときに `freq` は減らさない。`freq` は現在の選択状態ではなく累積の利用履歴を表すため。

### 2-4-3. 操作領域

- タコス個数の増減（`.count`）とブロック削除ボタンは、隣接による誤タップを避ける。
- ブロック削除ボタンは 44px 四方のタップ領域を持つ。
- 増減と削除の間隔は 8px とする。間隔を広げる方式ではなく、削除ボタン自体を大きくする方式を採る。

### 2-5. 設定タブ

- 表示、Slack連携、Googleログイン、タコス送信相手、日報プリセット、タコステンプレートを表示する。
- Googleログインカードは `currentUser` を表示する。
- ログインボタンは `googleLogin()`、ログアウトボタンは `googleLogout()` に接続する。
- 本日のタコス消費の手動調整欄は表示しない。

### 2-5-1. タコス送信相手のインライン編集

- 連絡先行にえんぴつアイコンを置く。編集UIは日報の案件名編集（えんぴつ→インライン入力→チェックで確定）と同じ方式。
- 編集状態は `state.editingContactId` / `state.editContactName` / `state.editContactMemberId` / `state.editingContactBackup` で保持する。バックアップは名前とメンバーIDの両方を持つ。
- ハンドラは `App.startEditContact(id)`、`App.setEditContactName(v)`、`App.setEditContactMemberId(v)`、`App.commitEditContact(id)`、`App.cancelEditContact()`。
- 編集行には名前とメンバーIDの2つの入力欄を出す。`data-k` は `edit-contact-{id}` と `edit-contact-member-{id}`。
- 入力の `oninput` では `render()` を呼ばない（IME対応）。確定時に `render()` と保存を行う。
- 確定時、名前とメンバーIDのどちらかが空なら保存せず、バックアップの値へ戻したうえでトーストを出す。文言は不足している項目に応じて出し分ける。
- 同名の連絡先が既にあっても拒否しない。同姓の相手が実在するため。連絡先の区別は `id` とメンバーIDで行う。
- 名前・メンバーIDの編集は連絡先一覧と宛先候補に反映する。作成中ブロックの `recipients` には反映しない（選択時点の宛先を保つ。パス独立の原則）。
- 一覧では、`memberId` が空の相手を未登録と分かる表示にする。

### 2-5-2. タコス送信相手の一括登録

- 入力欄には1行に1人ずつ `名前,メンバーID` の形式で貼り付ける。行の最初のカンマまでを名前、それ以降をメンバーIDとする。
- 名前の先頭にある `＠` `@` および空白は取り除く。
- 名前とメンバーIDのどちらかが空の行はスキップし、入力不足として件数に数える。
- 突き合わせは次の順で判定する。
  1. 名前が一致する連絡先が無い → 新規追加する。
  2. 名前が一致する連絡先が1件 → その連絡先の `memberId` を更新する。
  3. 名前が一致する連絡先が複数 → メンバーIDまで一致する連絡先があればそれを更新する。無ければスキップし、同名重複として件数に数える。
- 貼り付けた一覧に含まれない既存の連絡先は削除しない。
- 実行後、追加・更新・スキップの件数をトーストで表示する。スキップがある場合は内訳（同名重複／入力不足）を添える。
- メンバーIDの形式検証は行わない。空でないことのみを条件とする。Slack側の表記変更で登録できなくなる事態を避けるため。

### 2-5-3. タコステンプレートのインライン編集

- テンプレート行にえんぴつアイコンを置く。編集UIは 2-5-1 と同じ方式。
- 編集状態は `state.editingTemplateId` 等で保持し、ハンドラは `App.startEditTemplate(id)`、`App.setEditTemplateLabel(v)`、`App.setEditTemplateBody(v)`、`App.commitEditTemplate(id)`、`App.cancelEditTemplate()`。
- ラベルと文面の両方を編集できる。入力の `oninput` では `render()` を呼ばない（IME対応）。確定時に `render()` と保存を行う。
- ラベルまたは文面が空で確定した場合は元の値に戻す。
- テンプレートの編集は、既に作成済みのブロック本文には反映しない。テンプレートは値のコピー元であり、以後の適用にのみ効くため。
- 既存の追加用ハンドラ名（`setTplLabel` / `setTplBody` = 新規追加欄）と編集用ハンドラ名を混在させない。別名にする。

## 3. 出力設計

### 3-1. formatDay(groups)

- 案件カテゴリごとに `＜案件＞` を出力する。
- タスクごとに `X.Xh｜タスク名` を出力する。
- タスク名が空のタスクは出力しない。

### 3-2. outputBlocks()

```js
{
  block1: '退勤報告',
  block2: '今日やったこと',
  block3: '明日やること'
}
```

- `block1` は `greeting + today`。
- `block2` は `today` のみ。
- `block3` は `tomorrow` のみ。
- 区切り線は含めない。

### 3-3. copyBlock / copyAll

- 出力プレビュー内の個別コピーは Clipboard API を使う。
- `copyBlock(1)` は退勤報告を文章コピーする。
- `copyBlock(2)` は今日やったことを文章コピーする。
- `copyBlock(3)` は明日やることを文章コピーする。
- `copyAll()` は3まとまりを文章コピーする。
- これは `quickCopy()` とは別機能。

## 4. タコス設計

### 4-1. tacoPosts()

- 入力済みの宛先、本文、個数から投稿配列を作る。
- `merge` では同じ個数のブロックを1投稿にまとめる。
- `split` では宛先1人ごとに投稿を分ける。
- 各投稿は表示用・コピー用・Slack送信用の3つの文字列を持つ。

```js
{
  num, count, people, consume,
  previewText, // 画面表示用。宛先は ＠名前
  text,        // コピー用。宛先は名前のみ
  slackText    // Slack送信用。宛先は <@メンバーID>
}
```

- 宛先ラベルの生成は3つのヘルパーに分ける。
  - 表示用: メンバーIDがあれば `＠` + 名前、なければ名前のみ。
  - コピー用: 名前のみ。`＠` も `<@メンバーID>` も付けない。
  - Slack送信用: メンバーIDがあれば `<@` + メンバーID + `>`、なければ名前のみ。
- メンバーIDが無い宛先の `slackText` で `<@>` を生成しない。宛先候補はメンバーID必須のため通常は発生しないが、旧データが残っていた場合の保険とする。
- 同一ブロック内の連名は `join(' ')` で半角スペース区切りの横並びにする。`previewText`、`text`、`slackText` の3系統すべてで同じ並びにする。
- 投稿文の構成は上から「宛先（同一ブロック内は半角スペース区切り）」「本文」「タコス絵文字」。
- `merge` で複数ブロックをまとめる場合も、別ブロック間の `\n\n` は維持する。横並びにするのは同一ブロック内の連名だけとする。
- `merge` で同じ個数の複数ブロックをまとめる場合、ブロック間は `\n\n` で区切り、タコス絵文字はまとめた投稿全体の末尾に1セットだけ付ける。HeyTacoは1メッセージ内のタコス絵文字数とメンション人数を掛けて消費数を数えるため、ブロックごとに絵文字を付けると意図した消費数を超えるため。
- `split` では1投稿につき宛先1人となるため、従来どおり各投稿の末尾にタコス絵文字を1セット付ける。
- 出力プレビュー（`.post__body`）は `previewText` を表示する。人が読んで宛先を確認できるようにするため。
- `copyPost()` / `copyAllTacos()` は名前だけの `text` をコピーする。Slackへ貼り付けた後、利用者が各名前の前に `＠` を入力して候補から選ぶ。
- `sendTacos()` は全投稿の `slackText` を `postToSlack()` へ渡す。
- 出力プレビューのカード内に、Slackでのメンションに関する短い案内を常時表示する。開閉式にしない。

### 4-2. tacoDraftConsumption()

- 入力中ブロックの消費見込みを返す。
- 計算式は `宛先人数 × 個数`。
- 本文が未入力でも、宛先と個数があればゲージには反映する。
- 宛先追加、宛先削除、個数増減、ブロック削除で即時再描画される。

### 4-3. copyPost / copyAllTacos

- `copyPost(num)` は対象投稿の `text` を文章コピーし、消費数を加算する。
- `copyAllTacos()` は全投稿の `text` を `\n\n` で連結して文章コピーし、全投稿分の消費数を加算する。
- コピー前に `syncDailyUsage()` を呼び、日付が変わっていれば消費数をリセットする。
- 消費数を加算した直後に `render()` を呼び、固定サブヘッダーのゲージへ即時反映する。
- `tacoDraftConsumption() > 5` のとき、ゲージ背景・文字・バーを警告色にする。
- 個別コピー、一括コピー、Slack送信を重ねた場合の二重加算は許容する。

### 4-4. sendTacos

- タコスタブのSlack送信ボタンから呼ぶ。
- `state.webhook` が空の場合は「先に設定画面で送信先を登録してください」と案内し、送信しない。
- `tacoPosts()` の全投稿を取得し、投稿順に `postToSlack(post.slackText)` を実行する。
- 全投稿の送信に成功した後、`syncDailyUsage()` を呼び、全投稿の `consume` 合計を `accumulated` へ加算する。
- 加算後は `persist(true)` で保存し、再描画して送信完了を表示する。
- 送信に失敗した場合は顧客向けの案内を表示し、消費数は加算しない。

## 5. 永続化設計

### 5-1. localStorage

- 未ログイン時とオフライン時のバックアップとして使う。
- 主キーは `daily_report_state_v5`。
- `webhook_url` と `theme` は旧キー互換として維持する。

### 5-2. Firestore

- 保存先は `users/{uid}`。
- `loadFromFirestore()` はユーザー文書を一括取得する。
- `saveToFirestore()` は `{ merge: true }` で保存する。
- `saving` / `saveQueued` で多重保存を防ぐ。
- `debouncedFirestoreSave()` は1500msの遅延保存。

保存キー:

- `reportWork`
- `reportPresets`
- `tacoContacts`
- `tacoTemplates`
- `tacoBlocks`
- `tacoUsage`
- `tacoMode`
- `webhookUrl`
- `theme`
- `accentColor`
- `updatedAt`

### 5-3. 読み込み時のブロックID正規化

- ブロックIDの採番カウンタ（`UID`）は起動時に初期値から始まる。保存済みブロックは自身のIDのまま復元されるため、復元後にカウンタを進めないと、既存IDが再発行されてIDが重複する。
- 重複すると、ブロックの検索が先頭一致の別ブロックを返し、3件目の操作が2件目に反映される。削除は同IDのブロックをまとめて消す。
- `applyStoredData()` は、復元した全ブロックの数値IDの最大値までカウンタを進める。以後の `addBlock()` は必ず未使用のIDを採番する。
- 復元時点で重複または不正なIDを持つブロックがあれば、一意なIDへ振り直す。
- 振り直しが発生した場合は `persistLocal()` と（ログイン時）`saveToFirestore()` を実行し、保存済みデータからも重複を解消する。ローカル保存だけでは、他端末やFirestore側に残った重複データが直らないため。

### 5-4. 旧形式データの移行

- `tacoContacts` の各件に `memberId` が無い場合、空文字を補って復元する。
- `tacoBlocks[].recipients` が文字列の配列だった場合、`{ name, memberId }` の配列へ変換する。名前が一致する連絡先がちょうど1件あればその `memberId` を補い、同名が複数ある場合は空のままとする（どの相手か特定できないため）。
- 移行が発生した場合は `persistLocal()` と（ログイン時）`saveToFirestore()` を実行し、保存済みデータからも旧形式を解消する。ローカル保存だけでは、他端末やFirestore側に残った古いデータが直らないため。
- 移行後も、画面表示と出力は移行前と同じ見え方を保つ。

## 6. 認証・送信設計

### 6-1. Firebase Auth

- Firebase compat CDNを使う。
- `firebase.initializeApp(firebaseConfig)` を使う。
- `auth = firebase.auth()`。
- `db = firebase.firestore()`。
- `auth.onAuthStateChanged` を初期化時に登録する。
- `setPersistence` は呼ばない。

### 6-2. Slack

- `postToSlack(text)` は `fetch`、`mode: 'no-cors'`、`payload=` 形式を使う。
- 日報のSlack送信は `block1`、`block2`、`block3` を順に送る。
- タコスのSlack送信は各投稿の `slackText` を投稿順に送る。
- 日報とタコスは同じ `state.webhook` を使うため、送信先も同じになる。
