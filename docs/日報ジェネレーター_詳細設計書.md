# 日報ジェネレーター 詳細設計書

対象: `r-tsuruta-create/daily-report`
実装単位: `index.html` 単一HTML
最終更新: 2026-06-25

## 0. 実装概要

- 実装版HTMLのUI構造、CSS、画面関数を土台にする。
- Firebase Auth、Firestore、Slack送信は旧 `index.html` の関数名を維持して移植する。
- すべてを1つの `index.html` に統合する。
- 外部ビルドや生成バンドルに依存しない。

主要関数:

```js
viewHeader()
viewSubheader()
viewReport()
viewTacos()
viewSettings()
viewNav()
render()
outputBlocks()
tacoPosts()
googleLogin()
googleLogout()
userDocRef()
loadFromFirestore()
saveToFirestore()
debouncedFirestoreSave()
postToSlack(text)
```

## 1. データ設計

### 1-1. state

```js
state = {
  tab: 'report' | 'tacos' | 'settings',
  day: 'today' | 'tomorrow',
  today: Category[],
  tomorrow: Category[],
  greeting: string,
  presets: string[],
  contacts: TacoContact[],
  templates: TacoTemplate[],
  blocks: TacoBlock[],
  tacoMode: 'merge' | 'split',
  accumulated: number,
  usageDate: string,
  webhook: string,
  theme: 'light' | 'dark',
  tone: string
}
```

### 1-2. 日報

```js
Category = {
  id: number,
  category: string,
  tasks: Task[]
}

Task = {
  id: number,
  hours: number,
  name: string
}
```

- `today` は退勤報告として出力する本日分。
- `tomorrow` は朝会報告として出力する明日分。
- `groupsOf()` は現在選択中のタブのデータを返す。
- `state.day === 'today'` では `today`。
- `state.day === 'tomorrow'` では `tomorrow`。
- 出力では案件名に `＜＞` を付ける。

### 1-3. タコス

```js
TacoContact = {
  id: number,
  name: string,
  freq: number
}

TacoBlock = {
  id: number,
  recipients: string[],
  count: number,
  body: string
}

TacoTemplate = {
  id: string,
  label: string,
  body: string
}
```

- 宛先初期値は空。
- 実名やSlackユーザーIDはコードに書かない。

## 2. レイアウト設計

### 2-1. 固定シェル

- `.app` は `height: 100vh; height: 100dvh;`。
- `.header` は `position: fixed` で上部固定。
- `.subheader` は日報/タコス用の固定補助ヘッダー。
- `.nav` は `position: fixed` で下部固定。
- `.scroll` は絶対配置のスクロール領域。
- `.scroll` は下部ナビ分の `padding-bottom` を持つ。
- タブごとに `.app[data-tab="..."] .scroll` の `top` を切り替える。
- `.tab` には再描画時の `animation` を付けない。
- 入力、タスク追加、タコス変更などの通常操作で画面全体をフェードさせない。

### 2-2. 日報タブ

- `viewSubheader()` で退勤報告/朝会報告セグメントとワンタッチ流用ボタンを表示する。
- `viewReport()` は `groupsOf()` の結果を編集対象として表示する。
- 退勤報告タブでは `today` を表示・編集する。
- 朝会報告タブでは `tomorrow` を表示・編集する。
- 挨拶文カードは `state.day === 'today'` のときだけ表示する。
- 朝会報告タブでは挨拶文カードを出さない。

### 2-3. ワンタッチ流用ボタン

- `App.quickCopy()` が担当する。
- Clipboard API は使わない。
- 退勤報告タブでは `朝会報告の内容をコピー` と表示する。
- 退勤報告タブで押すと `state.today = cloneGroups(state.tomorrow)` を実行する。
- 朝会報告タブでは `退勤報告の内容をコピー` と表示する。
- 朝会報告タブで押すと `state.tomorrow = cloneGroups(state.today)` を実行する。
- `cloneGroups()` は案件カテゴリとタスクを新しい `id` で複製する。
- 挨拶文はコピーしない。
- 実行後は `render()` し、保存対象にする。

### 2-4. タコスタブ

- `viewSubheader()` でタコス固定サブヘッダーを返す。
- タコス固定サブヘッダーは `class="subheader meter"` にする。
- 固定サブヘッダー内に `タコスを贈る` タイトルを表示する。
- 固定サブヘッダー内に `本日のタコス消費` と `消費数 / 5` のゲージを表示する。
- `.app[data-tab="tacos"] .scroll` は固定サブヘッダーの高さぶん下げる。
- `viewTacos()` の本文先頭には別の「タコスを贈る」見出しブロックを置かない。
- 本文はすぐ宛先+文面ブロックから始める。
- 出力プレビュー内で `merge` / `split` を切り替える。
- コピー時に `accumulated` を加算する。
- 設定画面には `accumulated` の手動調整欄を置かない。

### 2-5. 設定タブ

- 表示、Slack連携、Googleログイン、タコス送信相手、日報プリセット、タコステンプレートを表示する。
- Googleログインカードは `currentUser` を表示する。
- ログインボタンは `googleLogin()`、ログアウトボタンは `googleLogout()` に接続する。
- 本日のタコス消費の手動調整欄は表示しない。

## 3. 出力設計

### 3-1. formatDay(groups)

- 案件カテゴリごとに `＜案件＞` を出力する。
- タスクごとに `X.Xh｜タスク名` を出力する。
- タスク名が空のタスクは出力しない。

### 3-2. outputBlocks()

```js
{
  block1: '退勤報告',
  block2: '今日やったこと',
  block3: '明日やること'
}
```

- `block1` は `greeting + today`。
- `block2` は `today` のみ。
- `block3` は `tomorrow` のみ。
- 区切り線は含めない。

### 3-3. copyBlock / copyAll

- 出力プレビュー内の個別コピーは Clipboard API を使う。
- `copyBlock(1)` は退勤報告を文章コピーする。
- `copyBlock(2)` は今日やったことを文章コピーする。
- `copyBlock(3)` は明日やることを文章コピーする。
- `copyAll()` は3まとまりを文章コピーする。
- これは `quickCopy()` とは別機能。

## 4. タコス設計

### 4-1. tacoPosts()

- 入力済みの宛先、本文、個数から投稿配列を作る。
- `merge` では同じ個数のブロックを1投稿にまとめる。
- `split` では宛先1人ごとに投稿を分ける。

### 4-2. copyPost / copyAllTacos

- `copyPost(num)` は対象投稿を文章コピーし、消費数を加算する。
- `copyAllTacos()` は全投稿を文章コピーし、全投稿分の消費数を加算する。
- コピー前に `syncDailyUsage()` を呼び、日付が変わっていれば消費数をリセットする。
- 消費数を加算した直後に `render()` を呼び、固定サブヘッダーのゲージへ即時反映する。
- `state.accumulated > 5` のとき、ゲージ背景・文字・バーを警告色にする。
- 個別コピー後に一括コピーした場合の二重加算は許容する。

## 5. 永続化設計

### 5-1. localStorage

- 未ログイン時とオフライン時のバックアップとして使う。
- 主キーは `daily_report_state_v5`。
- `webhook_url` と `theme` は旧キー互換として維持する。

### 5-2. Firestore

- 保存先は `users/{uid}`。
- `loadFromFirestore()` はユーザー文書を一括取得する。
- `saveToFirestore()` は `{ merge: true }` で保存する。
- `saving` / `saveQueued` で多重保存を防ぐ。
- `debouncedFirestoreSave()` は1500msの遅延保存。

保存キー:

- `reportWork`
- `reportPresets`
- `tacoContacts`
- `tacoTemplates`
- `tacoBlocks`
- `tacoUsage`
- `tacoMode`
- `webhookUrl`
- `theme`
- `accentColor`
- `updatedAt`

## 6. 認証・送信設計

### 6-1. Firebase Auth

- Firebase compat CDNを使う。
- `firebase.initializeApp(firebaseConfig)` を使う。
- `auth = firebase.auth()`。
- `db = firebase.firestore()`。
- `auth.onAuthStateChanged` を初期化時に登録する。
- `setPersistence` は呼ばない。

### 6-2. Slack

- `postToSlack(text)` は `fetch`、`mode: 'no-cors'`、`payload=` 形式を使う。
- 日報のSlack送信は `block1`、`block2`、`block3` を順に送る。
- タコスはSlack送信しない。
