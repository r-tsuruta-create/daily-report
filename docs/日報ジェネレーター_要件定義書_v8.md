## 0. 正しい完成仕様

- 見た目と画面ロジックは、実装版HTMLのデザインを土台にする。
- 認証、Firestore同期、Slack送信は旧 `index.html` の資産を移植して使う。
- 退勤報告タブは `today`、朝会報告タブは `tomorrow` を表示・編集する。
- 退勤報告の出力は `挨拶文 + today`。
- 朝会報告画面には挨拶文カードを表示しない。
- セグメント直下のワンタッチボタンは、文章をクリップボードへコピーするボタンではない。
- ワンタッチボタンは、反対側の案件カテゴリ/タスクを現在のタブへ流用コピーする。
- タコス画面は固定サブヘッダーに `タコスを贈る` と `本日のタコス消費` ゲージを表示する。
- タコスゲージは入力中の宛先人数と個数に即時追従する。
- 設定画面には本日のタコス消費の手動調整欄を置かない。
- Googleログインはページ更新後も保持する。

## 1. 最重要要件

- 各タスクは必ず「案件カテゴリ」「作業時間(h)」「タスク名」を持つ。
- 作業時間は 0.5h 刻みの増減と直接入力ができる。
- 案件カテゴリ単位で入力・表示・出力する。
- 実出力に区切り線は含めない。
- 同僚の実名やSlackメンバーIDをコードに直接書かない。ユーザーが登録したデータとして本人のデータ領域にのみ保存する。
- 生成バンドル由来の痕跡、外部ツール由来の展開タグ、大量のエスケープ済みテンプレート文字列は使わない。

## 2. 画面構成

- 下部タブは「日報」「タコス」「設定」の3つ。
- ヘッダーは画面上部に固定する。
- 下部ナビは画面下部に固定する。
- モバイルブラウザのアドレスバー伸縮対策として `100dvh` を使う。
- コンテンツスクロール領域には下部ナビ分の `padding-bottom` を確保する。
- タブ別の固定サブヘッダーは `.subheader` として画面上部に固定する。
- 入力、追加、削除、タコス変更などの通常操作で画面本体をフェードイン/フェードアウトさせない。
- 日本語入力中は入力欄を再描画で作り直さず、IMEの変換候補を消さない。

### 2-1. スクロール位置の維持

- 時間の＋−、タスク追加・削除、宛先追加・削除、テンプレート選択などの通常操作で、スクロール位置を維持する。
- 設定タブの連絡先一覧のように、画面内に独立したスクロール領域がある場合、その内側のスクロール位置も維持する。一覧を下までスクロールして編集・保存・削除しても、一覧が先頭へ戻らない。
- 入力欄へフォーカスを戻す処理が、スクロール位置を動かさない。
- スクロール位置が先頭に戻ってよいのは、下部ナビでタブを切り替えたときだけ。
- スクロール復元の過程で、先頭が一瞬見えるチラつきを出さない。

## 3. 日報タブ

### 3-1. データ

- `today`: 本日分。退勤報告として出力するデータ。
- `tomorrow`: 明日分。朝会報告として出力するデータ。
- 各配列の要素は案件カテゴリ。
- 各案件カテゴリは `category` と `tasks` を持つ。
- 各タスクは `hours` と `name` を持つ。

### 3-2. 表示と編集

- 日報タブ内に「退勤報告」「朝会報告」のセグメントを置く。
- 退勤報告タブは `today` を表示・編集する。
- 朝会報告タブは `tomorrow` を表示・編集する。
- 挨拶文カードは退勤報告タブだけに表示する。
- 朝会報告タブには挨拶文カードを表示しない。
- 案件名は画面上では `A案件` のように表示し、出力時だけ `＜A案件＞` とする。

### 3-3. 出力

コピー/Slack送信の出力は必ず次の3まとまりで生成する。

1. 退勤報告: 挨拶文 + 本日分
2. 今日やったこと: 本日分のみ
3. 明日やること: 明日分のみ

例:

```text
お疲れ様です。退勤いたします。
本日の作業内容です。

＜A案件＞
0.5h｜テスト手順書作成
＜B案件＞
1.5h｜MTG
1.0h｜設計書修整
```

### 3-4. ワンタッチ流用コピー

- セグメント直下にワンタッチボタンを置く。
- このボタンはクリップボードコピーではなく、反対側の案件カテゴリ/タスクを現在タブへ流用する。
- 退勤報告タブでは `朝会報告の内容をコピー` と表示し、`tomorrow` の案件カテゴリ/タスクを `today` へ上書きコピーする。
- 朝会報告タブでは `退勤報告の内容をコピー` と表示し、`today` の案件カテゴリ/タスクを `tomorrow` へ上書きコピーする。
- 挨拶文は流用コピー対象に含めない。
- 流用コピー後は localStorage とFirestore同期の保存対象にする。

### 3-5. プリセット

- 初期プリセットは「朝会・夕会等」「MTG」「設計」。
- ユーザーは設定タブから追加・削除できる。

### 3-6. 並び替え

- 案件カテゴリは、ドラッグで上下に並び替えられる。
- タスクは、同じ案件カテゴリの中だけでドラッグで上下に並び替えられる。
- タスクは案件カテゴリをまたいで移動しない。
- 操作は行左端のハンドル（⠿）を掴んで行う。
- マウス操作とスマホのタッチ操作の両方で動く。
- 掴んだ瞬間、対象のカード/行が浮き上がる（影と軽い拡大）。
- ドラッグ中、掴んだ要素はポインタ（指/マウス）に追従して動く。
- ドラッグ中、他の要素はリアルタイムに隙間を空けて避ける。瞬間的な入れ替え表示にしない。
- ポインタを離した位置で並びが確定する。着地でカクつき（ジャンプ）を出さない。
- 並び替え結果は保存対象にし、リロード後も保持する。

### 3-7. 稼働時間の色分けと表示位置

- 合計時間表示（計 X.Xh）は日報タブの固定サブヘッダー（.subheader）内に配置する。
- スクロール領域内には合計時間を表示せず、重複もさせない。
- スクロールしても合計時間の画面内の位置は変わらない。
- 判定対象は退勤報告・朝会報告それぞれの合計時間。両タブに適用する。
- 合計が8時間を超えたら赤・通常より大きい文字で表示する。
- 合計が8時間に満たなければ黄・通常より大きい文字で表示する。
- 合計が8時間ちょうどなら緑・通常サイズで表示する。

## 4. タコスタブ

### 4-1. 目的

- HeyTaco投稿文を作り、コピーする。
- 実送信はしない。
- コピー時に本日の消費数を加算する。

### 4-2. 固定サブヘッダー

- タコスタブでは固定サブヘッダーに `タコスを贈る` を表示する。
- 同じ固定サブヘッダーに `本日のタコス消費` と `入力中の消費見込み / 5` のゲージを表示する。
- 固定サブヘッダーは `.subheader.meter` とし、本文スクロール領域の上に隠れないよう配置する。
- 本文先頭には別の大きな「タコスを贈る」見出しブロックを置かない。

### 4-3. 投稿生成

- 1投稿は1つのタコス個数に対応する。
- 同じ個数のブロックは1投稿にまとめる。
- 個数が違うブロックだけ別投稿にする。
- 「個別で送る」モードでは宛先ごとに投稿を分ける。
- 投稿文は宛先、本文、タコス絵文字で構成する。
- 連名の宛先は1行に1人ずつ縦に並べる。
- 宛先の表示と出力を分ける。画面プレビューでは人が読める `＠名前` で表示し、コピーした文字列では Slack がメンションとして解釈する `<@メンバーID>` にする。貼り付けた時点でメンションが成立し、利用者が手で `＠` を付け直す必要をなくすため。
- メンバーIDを持たない宛先が残っていた場合は、壊れた `<@>` を出力せず、名前をそのまま出力する。
- 出力プレビューの近くに、Slackでのメンションに関する短い案内を常時表示する。

### 4-4. 消費メーター

- ゲージは `宛先人数 × 個数` の入力中合計で計算する。
- 宛先追加、宛先削除、個数増減のたびにゲージを即時再描画する。
- 入力中の合計が5個を超えたら、ゲージと表示を警告色に変える。
- コピーした時点で本日の消費履歴も加算する。
- 個別コピー後に一括コピーした場合の二重加算は許容する。
- 設定タブに手動調整欄は置かない。

### 4-5. 宛先

- 宛先は設定タブに登録した送信相手から選ぶ。
- 宛先候補は利用回数の多い順に並べる。同じ回数の場合は登録順とする。多数の相手から探す手間を減らすため。
- 宛先に選ぶたび、その相手の利用回数を1増やす。宛先から外しても利用回数は減らさない（利用履歴として扱うため）。
- メンバーIDが登録されていない相手は、宛先候補に表示しない。メンションが成立しない投稿文を作らせないため。
- 宛先に選んだ時点で、その相手の名前とメンバーIDを投稿側に控える。あとから設定タブで相手の登録内容を編集しても、作成中の投稿の宛先は変わらない。
- 宛先の選択は、名前ではなく登録相手そのものを指定して行う。同名の登録を許容しているため、名前だけではどの相手か特定できないため。
- 宛先は本人の localStorage / Firestore データ領域にのみ保存する。

### 4-6. 入力ブロック

- 宛先と文面の組を「ブロック」として複数作れる。
- 各ブロックは他のブロックと区別できる識別子を必ず持つ。識別子が重複すると、あるブロックの編集が別のブロックに反映されたり、削除が別のブロックを巻き込む。
- 保存データを読み込んだ時点で識別子が重複していた場合は、読み込み時に一意になるよう振り直し、その結果を保存する。
- 3件目以降のブロックを編集・削除しても、他のブロックが変化しない。
- 削除ボタンは 44px 四方のタップ領域を持つ。個数の増減ボタンは現行サイズを維持し、削除ボタンを大きくすることで誤タップを防ぐ。

## 5. 設定タブ

- 表示テーマとアクセントカラーを変更できる。
- Slack Incoming Webhook URL を保存できる。
- Googleログイン/ログアウトができる。
- 日報プリセットを追加・削除できる。
- タコステンプレートを追加・削除できる。
- 登録済みのタコステンプレートは、削除だけでなくラベルと文面を編集できる。
- 編集の入り方は、行のえんぴつアイコンをタップしてインライン編集（日報の案件名編集と同じ方式）。
- 本日のタコス消費の手動調整欄は置かない。

### 5-1. タコス送信相手の登録

- 送信相手は「名前」と「Slackメンバーid」の2つを持つ。
- 登録・編集のいずれでも、名前とメンバーIDの両方が入力されていなければ保存できない。片方が空の場合はエラーを表示し、元の値を保つ。
- 同じ名前の相手を複数登録できる（同姓の相手が実在するため）。
- メンバーIDの形式は制限しない。空でないことだけを条件とする。Slack側の表記が変わっても登録できなくならないようにするため。
- 一括登録は、1行に1人ずつ `名前,メンバーID` の形式で貼り付ける。
- 一括登録は既存の登録を置き換えず、次の規則で突き合わせる。
  - 名前が一致する登録が1件だけなら、その相手のメンバーIDを更新する。
  - 名前が一致する登録が複数ある場合、メンバーIDまで一致する相手がいればそれを更新する。特定できない行は登録せず、手動で確認するよう警告する。
  - 名前が一致する登録がなければ、新しい相手として追加する。
  - 貼り付けた一覧に含まれない既存の相手は削除しない。
- 一括登録の実行結果として、追加・更新・スキップの件数を表示する。
- 登録済みの相手は、削除だけでなく名前とメンバーIDを編集できる。
- 送信相手の編集は、連絡先一覧と宛先候補に反映する。作成中のブロックに追加済みの宛先には反映しない（選んだ時点の宛先を保つため）。
- メンバーIDが未登録の相手は、一覧では未登録であることが分かるように表示し、編集から登録できる。

## 6. 認証・同期・送信

### 6-1. Googleログイン

- Firebase Authentication の Googleログインを使う。
- `setPersistence` は明示しない。
- Firebase Auth のデフォルト永続化に任せる。
- 初期化時に `auth.onAuthStateChanged` を登録し、リロード後も `currentUser` を復元する。

### 6-2. Firestore

- 保存先は `users/{uid}`。
- 旧データは引き継がず、新構造で保存する。
- ユーザー文書を一括取得・一括保存する。
- ブロックや宛先ごとのループ取得はしない。
- `saveToFirestore()` は `{ merge: true }` を使う。
- `debouncedFirestoreSave()` は入力中の保存頻度を抑制する。
- ワンタッチ流用コピー、タコス消費加算、設定変更は保存対象にする。
- 保存済みデータの形式が古い場合（宛先が名前だけ、相手にメンバーIDがない等）は、読み込み時に現行形式へ変換し、変換が発生したらローカルへ保存する。Firestore へは通常の保存タイミングで反映されるため、移行処理から即時保存は行わない。

### 6-3. Slack送信

- `postToSlack(text)` は旧 `index.html` と同じシグネチャで使う。
- 日報のSlack送信だけに使う。
- タコスはSlack送信せずコピーのみ。
- Webhook URL は本人のデータ領域と localStorage 以外に出さない。

- 連絡先一覧を下までスクロールして編集・保存・削除しても、一覧が先頭へ戻らない。
- タコス画面を下までスクロールして個数を変えても、画面のスクロール位置が変わらない。
- タブを切り替えたときだけ、新しいタブが先頭から表示される。
