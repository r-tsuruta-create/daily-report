# リリース前検証チェックリスト

対象: 日報ジェネレーター `index.html`
最終更新: 2026-07-22

このチェックリストは、E2E（`tests/e2e.spec.js`）と `scripts/verify_v6.mjs` が保証する範囲と、
自動化していないため人が確認する範囲を分けて管理する。
記述は挙動型（「〜すると〜になる」）で書き、変数名や内部実装の有無で判定しない。

## 自動検証

リリース前に次を実行し、いずれもgreenであることを確認する。

```bash
node scripts/verify_v6.mjs
npx playwright test
```

### 日報タブ

- [ ] 日報タブでスクロールしても、合計時間は画面内の同じ位置に見え続ける。
- [ ] スクロール領域の中に合計時間が重複表示されない。
- [ ] 合計を8.5hにすると赤・大、7.5hにすると黄・大、8.0hにすると緑・通常サイズになる。
- [ ] 文字サイズが変わっても合計時間の枠サイズが変わらない。

### タコス テンプレート

- [ ] テンプレート行のえんぴつを押すと、既存のラベルと文面が入った状態で編集フォームが開く。
- [ ] 編集して保存すると一覧に反映され、リロード後も保たれる。
- [ ] テンプレートを編集しても、作成済み投稿の本文は変わらない。

### タコス 出力とメンション

- [ ] 出力プレビューの宛先が `＠名前` で表示され、`<@` の記法は表示されない。
- [ ] 投稿をコピーすると、コピーされた文字列の宛先が `<@メンバーID>` になり、名前がそのまま残らない。
- [ ] まとめモードでも、プレビューは `＠名前`、一括コピーは `<@メンバーID>` になる。
- [ ] 消費数の表示が「宛先人数 × 個数 = 合計」のまま変わらない。
- [ ] 出力プレビューの下に、Slackでのメンションに関する案内が操作なしで表示されている。

### タコス 送信相手

- [ ] 連絡先を編集して確定すると一覧に反映され、リロード後も保たれる。
- [ ] 連絡先を編集しても、作成中ブロックに追加済みの宛先は変わらない。
- [ ] 名前を空にして確定すると保存されず、エラーが表示され元の名前が残る。
- [ ] メンバーIDを空にして確定すると保存されず、エラーが表示され元の値が残る。
- [ ] 既存と同じ名前へ変更しても保存できる（同名を拒否しない）。
- [ ] `名前,メンバーID` を貼り付けて一括登録すると、名前が一致する既存の相手のメンバーIDが更新される。
- [ ] 同名が複数いてメンバーIDでも特定できない行はスキップされ、確認を促す件数が表示される。
- [ ] 一括登録に含まれない既存の相手が削除されない。
- [ ] メンバーIDが未登録の相手は宛先候補に表示されず、設定一覧には未登録表示で残る。
- [ ] 一度宛先に選んだ相手が、次の宛先選択で候補の上位に表示され、リロード後もその順序が保たれる。

### タコス 入力ブロック

- [ ] 宛先ブロックを3つにして3件目の本文を編集すると、3件目だけが変わり2件目は変わらない。
- [ ] 3件目で選んだ宛先が3件目だけに入る。
- [ ] 重複IDを含む保存データを読み込むと、ブロックIDが一意化されて保存され、リロード後も一意のままになる。
- [ ] 3つのブロックのうち1つを削除すると、その1つだけが消える。
- [ ] ブロックの削除ボタンが指で押せる大きさ（44px四方以上）を持つ。

### データ移行

- [ ] 旧形式（宛先が名前の文字列、連絡先にメンバーIDなし）の保存データを読み込むと、現行形式へ変換されて保存される。
- [ ] 旧形式から移行しても、宛先表示と投稿本文の見え方が変わらない。
- [ ] 宛先を選ぶと、その時点の名前とメンバーIDが保存され、リロード後も保たれる。

### スクロール位置

- [ ] 連絡先一覧を下までスクロールして編集を開始しても、一覧のスクロール位置が変わらない。
- [ ] 連絡先一覧を下までスクロールして編集を保存しても、一覧が先頭へ戻らない。
- [ ] 連絡先を削除しても、一覧のスクロール位置が保たれる。
- [ ] タコス画面を下までスクロールして個数を変更しても、画面のスクロール位置が変わらない。
- [ ] タブを切り替えると、新しいタブが先頭から表示される。

## 手動検証

自動化していない項目。リリース前に実機（スマホ・PC）で確認する。

### 並び替え

- [ ] 日報タブで案件カテゴリのグリップをドラッグすると、案件カードの順番が変わる。
- [ ] 日報タブでタスクのグリップをドラッグすると、同じ案件内のタスク順が変わる。
- [ ] タスクを他の案件カードへ引っぱっても、元のカードから出ない。
- [ ] 掴んでいる間だけ対象が浮き、離すとその位置に収まる。
- [ ] スマホのタッチ操作でも並び替えられる。
- [ ] 並び替えた順序がリロード後も保たれる。

### 認証・同期・送信

- [ ] Googleログイン後にページを更新しても、ログイン状態が保たれる。
- [ ] PCで編集した内容がスマホ側にも反映される（Firestore同期）。
- [ ] 日報のSlack送信が届く。
- [ ] タコスをコピーしてSlackに貼り付けると、宛先がメンションとして成立する。

### 入力まわり

- [ ] タスク名・案件名・挨拶文・タコス本文の入力中に、IMEの変換候補が消えない。
- [ ] 通常操作で画面全体がフェードしない。

### 文書

- [ ] 要件定義書と詳細設計書が、今回の変更内容を反映した状態で同梱されている。
- [ ] 実装と食い違う記述（過去の仕様の残骸）が残っていない。

## 運用メモ

- 現時点で、Push時にE2Eを自動実行するCI（GitHub Actions）は未整備。上記「自動検証」はローカル実行に依存している。CIを整備するまでは、リリース前に必ず手元で両コマンドを実行すること。
- テストのない要件は保証されていない要件として扱う。仕様を追加したら、対応するE2Eを同じ変更に含める。
