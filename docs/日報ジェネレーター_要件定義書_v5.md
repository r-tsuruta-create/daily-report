# 日報ジェネレーター 要件定義書 v5

対象リポジトリ: `r-tsuruta-create/daily-report`

本書は 2026-06-25 時点の実装済み `index.html` を正として、要件を整理したもの。

## 0. 最重要要件

- 各タスクは必ず「案件カテゴリ」「作業時間(h)」「タスク名」を持つ。
- 作業時間は 0.5h 刻みの増減と直接入力ができる。
- 案件カテゴリ単位で入力・表示・出力する。
- コピー/Slack送信の出力は必ず次の3まとまりで生成する。
  1. 退勤報告: 挨拶文 + 本日分
  2. 今日やったこと: 本日分のみ
  3. 明日やること: 明日分のみ
- 実出力に区切り線は含めない。

## 1. 実装方針

- 見た目と画面ロジックは、実装版HTMLのバニラ単一HTMLを土台にする。
- CSS、HTML構造、`state`、`outputBlocks`、`tacoPosts`、`viewReport`、`viewTacos`、`viewSettings`、`viewNav`、`render` の考え方を維持する。
- 認証、Firestore同期、Slack送信は旧 `index.html` の資産を移植する。
- 1つの `index.html` に統合する。
- 生成バンドル由来の痕跡、外部ツール由来の展開タグ、大量のエスケープ済みテンプレート文字列は使わない。

## 2. 画面構成

### 2-1. 全体

- 画面下部タブは「日報」「タコス」「設定」の3つ。
- ヘッダーは画面上部に固定する。
- 下部ナビは画面下部に固定する。
- モバイルブラウザのアドレスバー伸縮対策として `100dvh` を使う。
- コンテンツスクロール領域には下部ナビ分の padding-bottom を確保する。

### 2-2. ヘッダー

- 日報タブではアプリ名、日付、Googleログイン状態を表示する。
- Googleログイン中はアカウント名またはメール、可能ならアイコンを表示する。
- タコスタブと設定タブでも固定ヘッダーは維持する。

## 3. 日報タブ

### 3-1. データ構造

- `today`: 本日分。退勤報告として出力するデータ。
- `tomorrow`: 明日分。朝会報告として出力するデータ。
- 各配列の要素は案件カテゴリ。
- 各案件カテゴリは `category` と `tasks` を持つ。
- 各タスクは `hours` と `name` を持つ。

### 3-2. 退勤報告/朝会報告の切り替え

- 日報タブ内に「退勤報告」「朝会報告」のセグメントを置く。
- 退勤報告タブは `today` を表示・編集する。
- 朝会報告タブは `tomorrow` を表示・編集する。
- 挨拶文カードは退勤報告タブだけに表示する。
- 朝会報告タブには挨拶文カードを表示しない。
- `today` は退勤報告、`tomorrow` は朝会報告として出力する対応を崩さない。

### 3-3. ワンタッチコピー

- セグメント直下にワンタッチコピーボタンを置く。
- このボタンはクリップボードへ文章をコピーするボタンではなく、反対側の案件カテゴリ/タスク内容を現在開いているタブへ流用するボタン。
  - 退勤報告タブ: `朝会報告の内容をコピー` と表示し、`tomorrow` の案件カテゴリ/タスクを `today` へコピーする。
  - 朝会報告タブ: `退勤報告の内容をコピー` と表示し、`today` の案件カテゴリ/タスクを `tomorrow` へコピーする。
- コピー時は現在タブの案件カテゴリ/タスクをコピー元の内容で置き換える。
- 挨拶文はコピー対象に含めない。退勤報告の出力時は、既存の挨拶文 + `today` で生成する。

### 3-4. 出力フォーマット

案件名は画面上では `A案件` のように表示し、出力時だけ `＜A案件＞` とする。

例:

```text
お疲れ様です。退勤いたします。
本日の作業内容です。

＜A案件＞
0.5h｜テスト手順書作成
＜B案件＞
1.5h｜MTG
1.0h｜設計書修整
```

### 3-5. プリセット

- 初期プリセットは「朝会・夕会等」「MTG」「設計」。
- ユーザーは設定タブから追加・削除できる。

## 4. タコスタブ

### 4-1. 概要

- HeyTaco投稿文を作り、コピーする。
- 実送信はしない。
- タコスのコピー時に本日の消費数を加算する。

### 4-2. 投稿生成ルール

- 1投稿は1つのタコス個数に対応する。
- 同じ個数のブロックは1投稿にまとめる。
- 個数が違うブロックだけ別投稿にする。
- 「個別で送る」モードでは宛先ごとに投稿を分ける。

### 4-3. 消費メーター

- タコスタブ固定サブヘッダーに「タコスを贈る」タイトルを表示する。
- 本日の消費は同じ固定サブヘッダーの「本日のタコス消費」メーターに表示する。
- コピーした時点で加算する。
- 個別コピー後に一括コピーした場合の二重加算は許容する。
- 設定タブに手動調整欄は置かない。

### 4-4. 宛先

- 宛先は設定タブでユーザーが一括インポートする。
- 同僚の実名やSlackユーザーIDをコードに直接書かない。
- 宛先は本人の localStorage / Firestore データ領域にのみ保存する。

## 5. 設定タブ

- 表示テーマとアクセントカラーを変更できる。
- Slack Incoming Webhook URL を保存できる。
- Googleログイン/ログアウトができる。
- タコス送信相手を一括インポートできる。
- 日報プリセットを追加・削除できる。
- タコステンプレートを追加・削除できる。
- 本日のタコス消費の手動調整欄は置かない。

## 6. 認証・同期・送信

### 6-1. Googleログイン

- Firebase Authentication の Googleログインを使う。
- `setPersistence` は明示しない。
- Firebase Auth のデフォルト永続化に任せる。
- 初期化時に `auth.onAuthStateChanged` を登録し、リロード後も `currentUser` を復元する。

### 6-2. Firestore

- 保存先は `users/{uid}`。
- 本人データのみを一括取得・保存する。
- 旧データ構造の移行はしない。
- 保存対象は `reportWork`、`reportPresets`、`tacoContacts`、`tacoTemplates`、`tacoBlocks`、`tacoUsage`、`tacoMode`、`webhookUrl`、`theme`、`accentColor`。

### 6-3. Slack送信

- 日報の3まとまりをSlackへ送信できる。
- `postToSlack(text)` は旧実装のシグネチャを維持する。
- タコスはSlack送信せず、コピーのみ。

## 7. 完了確認項目

- 下部ナビが初期表示から画面下に固定される。
- ヘッダーが画面上部に固定される。
- セグメント直下にワンタッチコピーボタンが表示される。
- 退勤報告タブのワンタッチコピーは朝会報告の案件カテゴリ/タスクを退勤報告へ流用し、朝会報告タブのワンタッチコピーは退勤報告の案件カテゴリ/タスクを朝会報告へ流用する。
- Googleログイン後、ページ更新してもログイン状態が保持される。
- `setPersistence` を呼ばない。
- コードに同僚の実名・SlackユーザーIDが含まれない。
- 生成バンドル由来の痕跡、外部ツール由来の展開タグ、不要なエスケープ済み文字列が含まれない。
