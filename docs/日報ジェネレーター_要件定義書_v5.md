# 日報ジェネレーター 要件定義書 v5

対象: `r-tsuruta-create/daily-report`
実装単位: `index.html` 単一HTML
最終更新: 2026-06-25

## 0. 正しい完成仕様

- 見た目と画面ロジックは、実装版HTMLのデザインを土台にする。
- 認証、Firestore同期、Slack送信は旧 `index.html` の資産を移植して使う。
- 退勤報告タブは `today`、朝会報告タブは `tomorrow` を表示・編集する。
- 退勤報告の出力は `挨拶文 + today`。
- 朝会報告画面には挨拶文カードを表示しない。
- セグメント直下のワンタッチボタンは、文章をクリップボードへコピーするボタンではない。
- ワンタッチボタンは、反対側の案件カテゴリ/タスクを現在のタブへ流用コピーする。
- タコス画面は固定サブヘッダーに `タコスを贈る` と `本日のタコス消費` ゲージを表示する。
- タコスゲージは入力中の宛先人数と個数に即時追従する。
- 設定画面には本日のタコス消費の手動調整欄を置かない。
- Googleログインはページ更新後も保持する。

## 1. 最重要要件

- 各タスクは必ず「案件カテゴリ」「作業時間(h)」「タスク名」を持つ。
- 作業時間は 0.5h 刻みの増減と直接入力ができる。
- 案件カテゴリ単位で入力・表示・出力する。
- 実出力に区切り線は含めない。
- 同僚の実名やSlackユーザーIDをコードに直接書かない。
- 生成バンドル由来の痕跡、外部ツール由来の展開タグ、大量のエスケープ済みテンプレート文字列は使わない。

## 2. 画面構成

- 下部タブは「日報」「タコス」「設定」の3つ。
- ヘッダーは画面上部に固定する。
- 下部ナビは画面下部に固定する。
- モバイルブラウザのアドレスバー伸縮対策として `100dvh` を使う。
- コンテンツスクロール領域には下部ナビ分の `padding-bottom` を確保する。
- タブ別の固定サブヘッダーは `.subheader` として画面上部に固定する。
- 入力、追加、削除、タコス変更などの通常操作で画面本体をフェードイン/フェードアウトさせない。
- 日本語入力中は入力欄を再描画で作り直さず、IMEの変換候補を消さない。

## 3. 日報タブ

### 3-1. データ

- `today`: 本日分。退勤報告として出力するデータ。
- `tomorrow`: 明日分。朝会報告として出力するデータ。
- 各配列の要素は案件カテゴリ。
- 各案件カテゴリは `category` と `tasks` を持つ。
- 各タスクは `hours` と `name` を持つ。

### 3-2. 表示と編集

- 日報タブ内に「退勤報告」「朝会報告」のセグメントを置く。
- 退勤報告タブは `today` を表示・編集する。
- 朝会報告タブは `tomorrow` を表示・編集する。
- 挨拶文カードは退勤報告タブだけに表示する。
- 朝会報告タブには挨拶文カードを表示しない。
- 案件名は画面上では `A案件` のように表示し、出力時だけ `＜A案件＞` とする。

### 3-3. 出力

コピー/Slack送信の出力は必ず次の3まとまりで生成する。

1. 退勤報告: 挨拶文 + 本日分
2. 今日やったこと: 本日分のみ
3. 明日やること: 明日分のみ

例:

```text
お疲れ様です。退勤いたします。
本日の作業内容です。

＜A案件＞
0.5h｜テスト手順書作成
＜B案件＞
1.5h｜MTG
1.0h｜設計書修整
```

### 3-4. ワンタッチ流用コピー

- セグメント直下にワンタッチボタンを置く。
- このボタンはクリップボードコピーではなく、反対側の案件カテゴリ/タスクを現在タブへ流用する。
- 退勤報告タブでは `朝会報告の内容をコピー` と表示し、`tomorrow` の案件カテゴリ/タスクを `today` へ上書きコピーする。
- 朝会報告タブでは `退勤報告の内容をコピー` と表示し、`today` の案件カテゴリ/タスクを `tomorrow` へ上書きコピーする。
- 挨拶文は流用コピー対象に含めない。
- 流用コピー後は localStorage とFirestore同期の保存対象にする。

### 3-5. プリセット

- 初期プリセットは「朝会・夕会等」「MTG」「設計」。
- ユーザーは設定タブから追加・削除できる。

## 4. タコスタブ

### 4-1. 目的

- HeyTaco投稿文を作り、コピーする。
- 実送信はしない。
- コピー時に本日の消費数を加算する。

### 4-2. 固定サブヘッダー

- タコスタブでは固定サブヘッダーに `タコスを贈る` を表示する。
- 同じ固定サブヘッダーに `本日のタコス消費` と `入力中の消費見込み / 5` のゲージを表示する。
- 固定サブヘッダーは `.subheader.meter` とし、本文スクロール領域の上に隠れないよう配置する。
- 本文先頭には別の大きな「タコスを贈る」見出しブロックを置かない。

### 4-3. 投稿生成

- 1投稿は1つのタコス個数に対応する。
- 同じ個数のブロックは1投稿にまとめる。
- 個数が違うブロックだけ別投稿にする。
- 「個別で送る」モードでは宛先ごとに投稿を分ける。
- 投稿文は `＠宛先`、本文、タコス絵文字で構成する。

### 4-4. 消費メーター

- ゲージは `宛先人数 × 個数` の入力中合計で計算する。
- 宛先追加、宛先削除、個数増減のたびにゲージを即時再描画する。
- 入力中の合計が5個を超えたら、ゲージと表示を警告色に変える。
- コピーした時点で本日の消費履歴も加算する。
- 個別コピー後に一括コピーした場合の二重加算は許容する。
- 設定タブに手動調整欄は置かない。

### 4-5. 宛先

- 宛先は設定タブでユーザーが一括インポートする。
- 宛先は本人の localStorage / Firestore データ領域にのみ保存する。

## 5. 設定タブ

- 表示テーマとアクセントカラーを変更できる。
- Slack Incoming Webhook URL を保存できる。
- Googleログイン/ログアウトができる。
- タコス送信相手を一括インポートできる。
- 日報プリセットを追加・削除できる。
- タコステンプレートを追加・削除できる。
- 本日のタコス消費の手動調整欄は置かない。

## 6. 認証・同期・送信

### 6-1. Googleログイン

- Firebase Authentication の Googleログインを使う。
- `setPersistence` は明示しない。
- Firebase Auth のデフォルト永続化に任せる。
- 初期化時に `auth.onAuthStateChanged` を登録し、リロード後も `currentUser` を復元する。

### 6-2. Firestore

- 保存先は `users/{uid}`。
- 旧データは引き継がず、新構造で保存する。
- ユーザー文書を一括取得・一括保存する。
- ブロックや宛先ごとのループ取得はしない。
- `saveToFirestore()` は `{ merge: true }` を使う。
- `debouncedFirestoreSave()` は入力中の保存頻度を抑制する。
- ワンタッチ流用コピー、タコス消費加算、設定変更は保存対象にする。

### 6-3. Slack送信

- `postToSlack(text)` は旧 `index.html` と同じシグネチャで使う。
- 日報のSlack送信だけに使う。
- タコスはSlack送信せずコピーのみ。
- Webhook URL は本人のデータ領域と localStorage 以外に出さない。

## 7. 確認項目

- 退勤報告タブで `today` が表示・編集される。
- 朝会報告タブで `tomorrow` が表示・編集される。
- 退勤報告タブだけ挨拶文カードが表示される。
- 朝会報告タブには挨拶文カードが表示されない。
- 退勤報告出力は `挨拶文 + today` になる。
- 朝会報告側の出力は `tomorrow` のみになる。
- ワンタッチボタンはクリップボード文章コピーではなく、反対側の案件カテゴリ/タスクを現在タブへ流用する。
- タコスタブの空白位置に `タコスを贈る` と `本日のタコス消費` ゲージが表示される。
- タコスの宛先人数や個数を変えると、ゲージが即時に変わる。
- 入力中のタコス消費見込みが5個を超えると警告色に変わる。
- 設定画面に本日のタコス消費の手動欄が表示されない。
- 下部ナビとヘッダーが固定される。
- Googleログイン後、ページ更新してもログイン状態が保持される。
- `setPersistence` を呼ばない。
- 通常操作のたびに画面本体がフェードしない。
- タスク名、案件名、挨拶文、タコス本文の入力中にIME変換候補が消えない。
